Application Engineering

Three-Tier Business Microservices Tier Deep-Dive

Designed specifically for Sanskriti (Traditional Fashion & Beauty Store), providing modular separation of concerns.

1. Presentation Tier (ReactJS)

- Built with React 18, React Router v6, and Lucide icons.
- 9 Complete Views: Home (Hero, Banners), Sarees (Filters), Makeup, Bangles, Product Details, Cart, Checkout, Order Confirmation, and Store Operations Admin.
- State managed via persistent CartContext synchronized with localStorage.
- Served via hardened multi-stage Nginx Alpine with client-side SPA routing fallback.

2. Application Tier (Python Flask)

- Built using Flask 3.0, SQLAlchemy ORM, and Gunicorn WSGI (3 workers, 2 threads).
- 6 Modular Blueprints: /health (DB ping), /categories, /products (multi-attribute filtering), /orders (transactional placement), /customers, and /cart.
- Automatic inventory stock deduction and unique order number formatting.

3. Database Tier (PostgreSQL)

- PostgreSQL 15 engine containerized with persistent named volume postgres_data.
- 7 Relational Tables: categories, products, inventory, customers, orders, order_items, cart.
- 60 Seed Products: 20 Silk Sarees (Banarasi, Kanchipuram, Mysore), 20 Makeup items, and 20 Bangles.

DevOps Automation

Infrastructure as Code (IaC) & Continuous Delivery Pipeline

Eliminating manual provisioning and human error through declarative HashiCorp Terraform and automated Jenkins automation.

Terraform Cloud Infrastructure (AWS)

The entire cloud environment is defined as declarative code in terraform/:

  • AWS VPC: Dedicated 10.0.0.0/16 VPC with 2 public subnets across multiple AZs.
  • Security Groups: Strict firewall policies (80/443 for web, 22 for admin SSH, 3000 for Grafana).
  • AWS ECR: 2 private container repositories with automatic CVE scanning on push and 30-day lifecycle expiration.
  • AWS EC2: Ubuntu 22.04 LTS instance with an attached Elastic IP and IAM instance profile.
  • Cloud-Init Bootstrap: user-data.sh automatically installs Docker, Docker Compose, and AWS CLI v2 on first boot.

Jenkins 7-Stage Declarative Pipeline

Triggered automatically upon GitHub commits or pull request merges:

Stage 1-2: Checkout & Code Linting
Pulls repository, runs flake8 for Python backend and syntax checks for React frontend.
Stage 3-4: Docker Build & ECR Push
Builds multi-stage Docker images tagged with build numbers and commit hashes, pushes to AWS ECR.
Stage 5-6: SSH Remote Deploy & Smoke Test
Connects via SSH agent to EC2, runs docker compose pull, recreates containers, and runs HTTP health probes.

Configured Alert Rules & Thresholds

⚠️ High CPU Usage (> 85% for 5m)
Evaluates host CPU load and warns before node saturation impacts checkout transactions.
🚨 Host Memory Saturation (< 10% available)
Critical alert triggered before the Linux OOM-killer terminates microservices containers.
🚨 Service Container Down (up == 0)
Immediate critical alert fired within 60s if any frontend, backend, or database container crashes.
Presentation Cheat Sheet

POC & Team Presentation Guide

Use these concise, high-impact responses when explaining the architecture to stakeholders, engineering leads, or during technical interviews.

Q1: "Why use Nginx both as host reverse proxy and inside the frontend container?"
Answer: The host Nginx serves as the unified ingress controller and edge security boundary for the EC2 node, handling SSL termination, rate limiting, and port routing. The container Nginx is optimized purely for high-performance static SPA delivery and browser client-side routing fallback.
Q2: "How does the setup guarantee zero-loss of order transactions during updates?"
Answer: PostgreSQL data is stored outside the container filesystem in a persistent Docker named volume (postgres_data). During CI/CD redeployments, containers are updated and recreated without touching or resetting the storage volume.
Q3: "How does this architecture scale if traffic surges during festive seasons?"
Answer: Because the frontend and backend are completely decoupled and stateless, they can be scaled horizontally across multiple containers or shifted into AWS ECS / EKS behind an Application Load Balancer (ALB) with zero changes to application logic.
Q4: "What commands verify the entire system during a live demo?"
# Check running containers
docker compose ps

# Check API health
curl -s http://localhost:5000/health | jq .

# Check Prometheus targets
curl -s http://localhost:9090/api/v1/targets | jq .
